# 外部工具供给语义演进：接受「上游哈希供给」

最初的产品语义把「外部工具从哪来」定义为**我们自己封装并分发**：Tool Bundle（`.mcy`）是「装载外部二进制工具、以加密单文件形式分发的便携包」（GLOSSARY 初版，提交 `b0f3b05`），并依 b 裁定承担 b1「后续新增功能包的生产线」与 b2「可插拔信任模型」两项承诺。重构过程中该语义分五步位移——AES→Ed25519 签名（ADR-0003）→ 签名对象改 TAR 摘要 → 去签名与载体、改上游 zip（Manifest 方向）→ 删除造包工具与整层（B5）。**我们决定接受这一新语义并正式留痕**：外部工具的来源是**上游官方产物 + manifest 钉住的 SHA256**；产品不再自产、签名或分发二进制载体，「自供给（自产包）」不再是产品能力。

**Status**: accepted

**Supersedes**: ADR-0003 的核心决定（以签名作为信任锚）。

## Considered Options

- **恢复最小自供给**（约 30 行 zip 打包工具 + manifest 自托管 URL，不引入签名）：暂不采用——它能替无官方归档的 Ghostscript/LibreOffice 找回便携供给，但需先用真实使用体验确认需求强度，之后再评估（恢复路径已记入 Consequences）。
- **恢复完整 `.mcy` 语义**（签名 + 加密载体）：拒绝——等于推翻 B 方向；且单维护者 + 内嵌公钥在威胁模型上等价于内容哈希，却附带密钥 ceremony 与 `cryptography` 依赖（ADR-0003 修订记录）。
- **不记录，维持现状**：拒绝——产品语义已实质变更；不留痕会让后续维护者（含未来的自己）按旧语义判断「该怎么供给」。

## Consequences

- **供给面收窄**：无官方归档的工具（Ghostscript、LibreOffice 仅发行安装器）不再由应用自供给，退回「检测用户系统安装」；界面既有「未安装 / 功能受限」提示覆盖该路径。
- **信任模型统一**：来源 = 上游 URL + SHA256（`plugins/manifest.json`）；`GLOSSARY.md` 的 Tool Bundle 保持 `[已退役]`，新代码一律用 Manifest 项 + 预置包。
- **载体代价已留档**：LZMA→DEFLATE 使分发体积由 23.46MB 升至 40.20MB（pandoc），换来解压更快、峰值内存更低（ADR-0003 修订记录有实测）。
- **恢复路径明确**：若真实使用后确认需要自供给，最小改法是「zip 打包工具 + manifest 自托管 URL」（无需复活签名），届时先开新 ADR。
- **决策留痕**：本条为事后追认。五步中前四步均经维护者逐次确认；第五步（B5 删除整层）在自动续跑指令下按维护者倾向执行、经维护者复核接受。记录于此，避免「语义由谁、何时改变」失考。
